## Thesis (confirmed E2)

The query pipeline performs work proportional to **N** (document count) in stages that should scale with **K** (text-hit count). Pass 3 BDN confirms this for materialization, general facet apply, and cold NaturalSort — not as three unrelated hotspots, but one algorithmic pattern.

## Corrected measurements (pass 3.1)

### E2E pipeline — measured hit counts

Query `"report"` (Within) on file corpus @ 100k:

| Metric | Value |
|--------|------:|
| **textHitCount** (before facet) | **10,000** |
| **postFacetHitCount** (size ∈ [1KiB, 1MiB]) | **4** |

Do **not** describe this scenario as "~20 hits". The facet collapses 10k text candidates to 4 results; cold NaturalSort still builds a full **N=100k** permutation first.

| Scenario | Mean (5 iter) |
|----------|---------------|
| 0 text hits + NaturalSort cold | **31.2 ms** (high variance — mechanism confirmed, prefer ~22 ms component benchmark for stable timing) |
| Within+Facet+NaturalSort cold | **24.9 ms** |
| Within+Facet SnapshotOrder | **185 μs** (~**134×** vs NaturalSort path) |

### NaturalSort — precomputed K keys (fair prototype)

Earlier `NaturalSortKOnlyNaive` rebuilt sort keys inside the sort comparator → inflated allocations at large K (353 MB @ K=100k). **Fixed prototype:** build each `NaturalSortKeyBuilder.Build()` exactly once, then `Array.Sort(keys, ordinals)`.

| K / 100k | Global permutation | Sort K (precomputed) | Ratio |
|---------:|-------------------:|---------------------:|------:|
| 0 | ~22–66 ms | **164 μs** | **~140×** |
| 1 | **21.8 ms** | **175 μs** | **~124×** |
| 10 | **21.8 ms** | **30 μs** | **~730×** |
| 100 | **23.4 ms** | **223 μs** | **~105×** |
| 1,000 | **22.3 ms** | **248 μs** | **~90×** |
| 10,000 | **21.7 ms** | **2.5 ms** | **~8.7×** |
| 50,000 | **22.7 ms** | **9.0 ms** | **~2.5×** |
| 75,000 | **22.5 ms** | **14.4 ms** | **~1.6×** |
| 100,000 | **22.9 ms** | **19.6 ms** | **~0.85×** (crossover) |

**Empirical crossover:** sort-K wins until roughly **90% of N**; global cached permutation wins at ~100%. Do **not** ship a fixed "1%" or "5%" threshold — measure at runtime or use a conservative constant (~80% of N) derived from BDN on target corpus.

**Hybrid algorithm (production):**

```
K = resultSet.GetTrueCount()  // or enumerate once
if K == 0 → return []
if K == 1 → return [single record id]
if K < threshold(N) → enumerate K, build K keys once, sort K, materialize
else → GetSortedPermutation(), filter by bitset (current warm path)
```

Cold path must skip global build when K==0 (biggest typeahead win).

### Facet — F-02 part two

General `FacetFilterEvaluator.Apply()` is O(N) flat ~63 μs @ 100k regardless of K.

| K | O(N) scan | Facet on K (in-place) | Speedup |
|--:|----------:|----------------------:|--------:|
| 10 | 64 μs | **~1.1 μs** | **~57×** |
| 1,000 | 64 μs | **~3.9 μs** | **~16×** |
| 10,000 | 63 μs | **~29 μs** | **~2.1×** |

**Hybrid facet:**

- **Sparse K** (K ≪ N): enumerate set bits → evaluate facet predicates only on those ordinals (in-place clear + re-add, or filter during enumeration).
- **Dense K** (K approaching N): keep full column scan + SIMD `IntersectWith` (current path may win on implementation/cache behavior).

Intersect-second-bitset prototype is conservative; in-place re-add is tighter and sufficient for 0.5.6.

### Bitset materialization

`CopySetBitOrdinals()` + enumerate materialization: **~90×** at K≤100, **~27×** at K=1k. Crossover ~50% bit density. **Ship with high confidence.**

### Build allocation — defer from 0.5.6 unless integrated A/B wins

Isolated span-aware pool: **4.65 ms / 3.0 MB** vs current **7.37 ms / 10.1 MB** on token loop. Prototype uses raw `Ordinal` span lookup — must be **normalization-aware** (case-insensitive) before integrated full-rebuild A/B. Not blocking selectivity pipeline.

### FileMask glob — lower priority post-selectivity

Real `*.pdf` @ 100k FileMask: **260 μs** vs Default (broken) **44 μs**. Important for benchmark hygiene; lower priority than selectivity pipeline after above wins.

## Recommended 0.5.6 implementation order

1. **`FastBitSet.CopySetBitOrdinals`** → use in `MaterializeResults` SnapshotOrder path (and anywhere else scanning all N ordinals).
2. **Selectivity-aware facet** for non-Exact paths: if sparse K, facet on enumerated hits only; else current `Apply()`.
3. **Selectivity-aware NaturalSort** hybrid with K==0 early exit, K==1 fast path, precomputed sort-K below crossover threshold.
4. **BDN gate** in CI/manual: re-run `NaturalSortCrossoverBenchmark` + `SelectivityPipelineBenchmark` on x64; document threshold constant from CSV.
5. **Optional same release:** normalization-aware span pool if integrated rebuild A/B confirms ≥15% rebuild win.

## Out of scope for 0.5.6

- Cross-snapshot NaturalSort key cache (global permutation cache per snapshot is enough once K-threshold logic exists).
- Glob bigram pruning (separate track).
- FacetValues compact storage / per-document dictionary dedupe.
- ARM64 pass 3 re-measure (follow-up before claiming cross-platform threshold).
